## 1. 本步新增的运行接入

- `job_manifest.py` 从冻结的 R01/R02 成员和实验矩阵展开精确 fit/model/prediction 单元。操作点、来源、方法、视图、折、训练与测试 ID 分别绑定，不将样本×方法数量当成独立样本数。
- `job_runtime.py` 验证 FREEZE/RESOURCE 清单、实际文件、运行时版本、计划与成员。`FormalFitRequest` 的 14 个字段逐项核对；通过内容校验后仍需另行批准的阶段授权。当前 R04 没有这类真实授权。能力由已校验 context 发放，不能由 synthetic 标记或重命名 ID 获得。
- `access.py` 新增只含本折 train 数据的能力对象，测试和描述分区根本不装入此对象。R03 的 `core_view` 和 `single_surface_view` 在这个对象上处理的只有 train；外层转换在模型保存、加载和冻结之后另行执行。
- `selector.fit`、固定基线从能力取得作业血缘和拟合范围，并在拟合开始前核对方法、操作点。正式作业描述使用真实 LOEO/LOCO、R02 缓存来源和精确成员；合成模型继续显式标记 BUILTIN_SYNTHETIC/SYNTHETIC_ONLY。没有在训练后修改模型 JSON 或伪造 freeze_time。
- `runner.py` 提供统一 dispatcher：核对作业 → train 读取/转换/选择 → 写入并加载模型/编码器 → 生成冻结收据 → outer 输入转换/预测 → 保存并关闭/对账预测 → 独立读取评价侧标签。训练、预测与评价记录实际成员及读取时点；所有 worker 均由 dispatcher 派发新进程。
- 持久化预算账本保存已预留的拟合次数、实际耗时和作业顺序，使用独占锁。R01 的总上限仍为 **200 个拟合尝试、21,600 秒、单求解器线程**。单作业同时受原 60/120 秒选择器上限及 30 秒读取/保存开销上限约束；总耗时按整个 dispatcher 调用的单调时钟累计，包含准备与关闭开销；预算耗尽后仍完成必要对账，不能据此再启动新作业。硬 watchdog 包含资源验证和子进程启动。正在执行的作业超时记 FAILED，未启动且预算已耗尽记 NOT_RUN_BUDGET_EXHAUSTED。崩溃预留额度不会被自动归零，也不自动重试。
- `oof.py` 先逐 expected fold/model/stage 对账，再汇总多折模型。按实验、协议、切分、方法、操作点、来源、视图、评价轨和材料来源分组。重复、跨折、模型收据不符及混合操作点被拒绝；漏折、失败、空模型保留。缺模型时原子/子句预期单元数未知，覆盖率标 NOT_EVALUABLE，阶段/标签分母保留。

预算优先级为 R01 原顺序，同级按精确 job_id 排序，作用于当前已授权阶段；不会为了运行优先级较高的未来步骤而越权启动它，也不会读取外层指标重排。后续阶段必须继续使用获批的同一预算账本。
