## 已确认问题与改动

原 `R04_freeze/isolated_validation/budget_count/OOF.json` 保留原样。其中一折完成，另一折 `NOT_RUN_BUDGET_EXHAUSTED`、`model_id=null`；原阶段分母为 18，但原子覆盖率错误地报告 18/18、1.0、OK。原 R04 验收未覆盖这个分支，原报告、日志、验收状态和保存的错误例没有改写。本修订的发现及证据单独记录在 `CHANGE_RECORD.json`。

`oof.py` 现在按每个模型单元自己的回执确定预期原子/子句数量，不从其他折借用数量。`runner.failed_rows` 的未知预期数量使用 null。`evaluation.py` 在总体和每个分层内统一处理未知数量；不可评估的完整范围不保留旧数值。原始预测/回执未被修改，归并只操作副本。

| 输入情况 | 覆盖率处理 |
|---|---|
| 完全没有回执 | 预期数量未知；NOT_EVALUABLE，value / denominator / expected_denominator 均为 null |
| 有失败、超时、未运行回执，但没有 model_id | 同上；即便旧占位行写了 0，也不会当作已知零数量 |
| 有 model_id，但缺少 atoms 或 clauses 数量 | 对应覆盖率未知；另一类数量若已知则独立计算 |
| 模型和数量已知，部分预测缺失或失败 | 使用该模型原有预期单元分母；缺失预测的可用数量为 0 |
| 合法 EMPTY_MODEL 或明确常数基线 | 保留已知的零单元数量；零分母覆盖率仍不可评估，expected_denominator=0 |
