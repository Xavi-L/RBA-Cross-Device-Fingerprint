AUDIENCE AND PURPOSE
This revision addresses a reader who understands computer systems but has not
read the HybridGuard paper. The figure should communicate the target (integrity
of reported environment information), the inputs, one concrete trigger mechanism,
and the meaning of each result without requiring the paper's internal notation.

ILLUSTRATIVE MEMORY CHECK
This is a synthetic example of the implemented relation, not an experimental
measurement or a performance claim. Assume valid and applicable operands from
one bound App record: Native memory = 4 GiB, App Web memory = 8 GiB.
The allowed Web upper bound is 2^(ceil(log2(4))) = 4 GiB. The reported Web value
8 GiB exceeds that bound, so the selected memory check triggers.

The relation is an upper-envelope check, not an equality test. For example,
a lower Web exposure may remain compatible. Native measurements are contextual
observations, not trusted ground truth. The example illustrates a check result;
another selected dependency's execution failure still takes precedence at the
detector level. It does not assert that every manipulation creates a detectable
cross-view conflict.

RESULT SEMANTICS
- Triggered corresponds to T after the selected condition's polarity is applied.
- A definitely false result corresponds to F, not a guarantee of authenticity.
- Missing, unusable or inapplicable evidence may leave a condition undetermined
  (U). It is not automatically a false result.
- Execution or association failure of a selected dependency yields FAILED before
  considering triggers, even if another selected condition is T.
- Without such failure, any T yields a manipulation alert. A nonempty selected
  set containing only F yields no alert. The remaining unresolved cases yield
  insufficient evidence. Empty selected sets have a distinct implementation
  status; the illustrated deployed configurations have selected checks.
- An alert flags potential report manipulation. It is not proof of a particular
  attack, and no alert does not certify safety, authenticity or a device identity.

OBSERVATION AND CONFIGURATION BOUNDARIES
Native, WebView Host and App Web reports retain their values, field states,
receipts and collection context. The App reports belong to a bound execution;
this does not imply atomic sampling. The optional Browser is a separate Web
execution that must be validly linked. No synchronized universal sample is
assumed. Host-Web geometry is a separate study, not a selected Full App check.

App only in the figure corresponds to Full App. App + linked Browser corresponds
to Full App + C1. C1 compares finite, usable App Web and Browser timezone offsets
using the same Web sign convention. C1 is active only in the paired mode. Its
current implementation has no timestamp gate; asynchronous normal setting
changes remain an unresolved limitation. There is no sequential fallback or
runtime retraining. Only failures relevant to selected checks fail the detector.

Candidate checks and development data independently feed constrained offline
selection. Fixed rules and parameters govern both check evaluation and result
combination. Construction constrains normal alarms, definite-output coverage,
and complexity. Boxes depict logical responsibilities, not separate services.

PROPOSED FIGURE CAPTION
System design of HybridGuard. Fixed integrity checks evaluate current Android
environment reports. Native, WebView-host and JavaScript observations from one
App execution are associated; a validly linked external Browser supports an
optional timezone-offset check (C1). The memory example illustrates an
upper-bound violation on valid inputs. Only selected checks contribute to the
result: execution or association failures take precedence and suppress a
detection decision; otherwise any trigger yields an alert, a nonempty set of
all definitely false conditions yields no alert, and unresolved cases yield
insufficient evidence. No alert does not establish authenticity. Offline
selection constrains normal alarms, definite-output coverage and complexity.

REVIEW SCOPE
A simulated first-reading review without paper context identified ambiguity in
the detection target, T/F polarity, C1, binding context and failure handling.
That was a design diagnostic, not a human-reader study. This revision addresses
those gaps in the figure and caption. Actual readers may still require the
method section for formal admissibility conditions, selection constraints and
complete check definitions.

The exported SVG/PDF were rendered for visual review. The memory example and
result mapping were checked against the method source. Repository files were
read for fidelity; no GitHub commit or source file was changed.
