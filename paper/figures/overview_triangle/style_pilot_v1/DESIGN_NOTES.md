## 实际设计变化

**图文关系。** 撤掉三个节点包围全部文字的卡片轮廓，三种原有浅色只衬托主对象，名称、角色和说明在旁侧对齐。图标横跨完整说明区的高度，成为节点的组成主体。Native 以手机及屏幕内设置滑杆区分系统侧；Host 以较重外壳包容较轻内页；App Web 以折角页面、JS 和两条无值属性记录线为主体。三个对象来自同一套 Tabler 图形语言，再作同一组定制，详情见资源清单。

**比例与负空间。** 手机可视机身约 72 × 108 单位；Host 外壳约 110 × 85 单位；App Web 页面约 77 × 99 单位。Host 内页完全位于白色内容区中，外框线宽约 3.90 单位、内页约 1.93 单位，包容层级通过形状及重量共同表达。内页 JS 在小尺寸下为辅助标识，识别 Host 首先依赖外壳包含页面的形状，不能声称每个图标细节都在屏幕预览中同等清晰。

**关系标签。** 撤掉三个关系标签的矩形外框，改为靠边排字和短引线。蓝色比较实线、赭色比较虚线与灰色无箭头点线分别保留；灰边仍明确写 No detection rule，几何边仍写 Not in current detector。没有用大白块遮断关系线，也没有新增从一个节点流向另一个节点的数据循环。中央只保留 Cross-check / reported properties。

**分组与颜色。** 保留同设备浅灰实线边界与 App 虚线边界，因为二者表达范围；节点与标签无需再套一层框。Native `#faf0e2`、Host `#e9f0f9`、App Web `#edf3e9` 的底色与当前稿一致。关系状态色、红字 `#D62828` 也未改变。图标局部加深轮廓、增加小块填充；移除原三角淡底，留白由三条边组织。

**文字与线条。** 19 条正文/分组文本与冻结文案逐项一致（Memory and timezone 出现两次），不靠删字或压缩字体腾空间。正文保持 28–29 单位，节点名称 34、关系名称 28/30、Cross-check 38，与当前稿对应大小一致。统一 Times New Roman / Times / serif；SVG 保留原生文本，JS 也采用文本。没有 textLength、挤字距、非等比文字缩放或嵌入栅格图。主要对象轮廓约 3.3–3.9 单位；蓝比较线 3.2、其余关系 2.6、引线与范围线 1.5 单位。

## 排版尺度与已完成检查

正式总图宽 **180 mm**、viewBox 宽 1800；选取当前 `(x=24, y=104, w=1160, h=590)` 区域作基线。因此推荐样块为 **116 × 59 mm**，占总图宽约 **64.4%**；App 虚线边界宽 112 mm。没有把局部图放大至 180 mm 冒充论文尺度。28–29 单位正文对应约 **7.94–8.22 pt**。

SVG 以毫米声明尺寸；PNG 为 2320 × 1180 px，写入 508 dpi，与 116 × 59 mm 对应。96 dpi 样块预览为 438 × 223 px；整图预览宽 680 px。屏幕上的真实毫米大小仍取决于显示器及查看器缩放，尚未进行纸质打印检查。

已检查：

1. **预计排版尺寸**：查看 116 mm / 96 dpi 旧新对比及样块预览，检查主要对象、字级和关系标签。
2. **放大细节**：查看最终节点与图标裁图；修正初稿 Host 内页突出外壳的问题，保留屏幕、折角和容器留白。节点详情从同一个 SVG 提取，仅隐藏邻接关系与边界以避免裁入无关半个字符，节点自身未另画。
3. **整图位置**：查看 180 mm 总图位置和完整预览，确认样块仍在原三角占比内；图标视觉存在感增强，正文与周边原稿仍同尺度。其余模块的风格协调留待后续明确授权。
4. **公平参考比较**：打开两张完整图的同宽预览和保留父图比例的局部对照；没有对其中的节点单独缩放以制造效果。
5. **内容和输出**：Chrome 独立渲染与 Sharp 导出；检查文本无交叠、关系线未穿过文本、无画布越界、三条边各自状态保持、无栅格图元，确认五个正式文件与本轮开始副本逐字节相同。详见 CHECK.json。

## 六项自检与边界

| 问题 | 当前判断与依据 |
|---|---|
| 三个观察位置能否通过图形区分？ | 自检可区分手机、内含页面的应用外壳、JS 页面；确切角色由保留的名称共同解释。未做外部读者识别实验。 |
| 图标是否成为节点组成主体？ | 主对象占据说明区高度，三个文本行统一在图形旁侧，而不是标题角落的小徽标。 |
| 标签是否能对应关系边？ | 斜边标签置于各自边外侧并用短引线关联；几何标签紧邻底边下方。三种线型和状态文字同时存在。 |
| 是否体现参考的朴素与细节组织？ | 采用局部浅色、对象与文字组合、轮廓/填充/流程线分层；细节统一在手机、外壳和共用页面的比例上。完成度为本轮内部视觉判断，等待用户确认。 |
| 文字信息是否保持？ | 19 条正文/分组文本逐项一致；说明的字号未降低，未增加字段数、候选编号或虚构属性值。 |
| 是否新增可信、安全或完整互证闭环暗示？ | 无盾牌、锁、认证勾或可信芯片；灰边无箭头，几何保留未入模状态，两条比较边均为两端开放箭头。三角不是数据顺序流。 |

**未完成/未宣称完成**：纸质打印、外部读者或导师验收、整张总图统一重绘、Browser/时区/Offline/检测区及评价条带的风格扩展、正式 LaTeX 更新、投稿级验收。其余方法区域未在样块展示，不代表从方法删除。

## 再生成

在仓库根目录执行（输出仅写入本目录）：

```sh
python3 -B paper/figures/overview_triangle/style_pilot_v1/build_sample.py
node paper/figures/overview_triangle/style_pilot_v1/render_sample.cjs
node paper/figures/overview_triangle/style_pilot_v1/check_sample.cjs
```

渲染使用本机已配置的 Codex Node 依赖目录，可通过 `RBA_NODE_MODULES` 指定含 Sharp 和 Playwright 的目录；独立检查默认使用本机 Google Chrome，可用 `RBA_CHROME` 指定可执行文件。参考预览读取已保存的 Figure 1 裁图，基线比较读取本轮冻结副本。生成器不导入正式绘图脚本，不写正式输出，不访问实验入口。
