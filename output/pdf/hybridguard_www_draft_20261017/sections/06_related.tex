\section{Related Work}
\subsection{Browser Fingerprinting and Spoofing}
Report manipulation and relationships among fingerprint attributes are established research topics. Gummy Browsers studies targeted impersonation through fingerprint copying and browser modifications~\cite{liu2022gummy}. Fp-Scanner examines inconsistencies introduced by countermeasures, including disagreement between JavaScript and HTTP user-agent reports and constraints involving browser, OS, and rendering behavior~\cite{vastel2018fpscanner}. Picasso checks claimed browser and OS classes using canvas challenge--response and a server-side response dictionary~\cite{bursztein2016picasso}. Fp-Scanner and Picasso already use inconsistencies or behavioral evidence to scrutinize reported attributes.

Measurement studies provide complementary evidence. Him of Many Faces analyzes benign and adversarial fingerprints collected through website JavaScript and native mobile SDKs, covering network, browser, and user attributes~\cite{wu2023manyfaces}. Its traffic classifications do not directly label whether an environment report was modified. FP-Inconsistent detects evasive bots using spatial incompatibilities within requests and temporal changes across requests associated through cookies or IP addresses~\cite{venugopalan2025fpinconsistent}. Its analysis already identifies consistency-preserving evasion and normal-user alarm risks.

BrowserFM connects feature models of fingerprints, system hardware/software, and browser configurations to represent dependencies and analyze configuration changes~\cite{huyghe2025browserfm}. Structured relations and associated context therefore have clear precedents. \hg focuses on semantic references within an Android hybrid Web execution: Native and Host observations contextualize App Web reports, while controlled modifications and normal changes test when those references distinguish manipulation. The comparison concerns the evidentiary role of these references, including their applicability and availability.

\subsection{Cross-Browser and Cross-Context Fingerprinting}
Fingerprinting supports identification and security uses, as surveyed by Laperdrix et al.~\cite{laperdrix2020browser}. Alaca and van Oorschot analyze fingerprinting for augmenting authentication, including stability and spoofing resistance~\cite{alaca2016device}. Spooren et al. find similarity and predictability limitations in mobile fingerprints collected for an authentication system~\cite{spooren2015harmful}.

Cao et al. derive OS- and hardware-dependent features through browser APIs and rendering tasks, then select features stable across browser pairs for device identification~\cite{cao2017crossbrowser}. Their design accounts for browser capabilities and tests rendering stability under window and zoom changes. Such browser-mediated measurements differ from our associated Native measurements and Host container observations. Both approaches use relationships across observations, but identifying a device across browsers and assessing a current report against contextual constraints ask different questions. \hg evaluates neither identity uniqueness, cross-browser linkage accuracy, authentication success, nor production fraud detection. Its external Browser extension remains a separate execution context, outside the Native--Host--App Web model.

\subsection{Android WebView and Cross-Boundary Analysis}
WebView research directly overlaps our observation setting. Tiwari et al.'s WVProfiler instruments Android WebView loading calls to associate applications with exposed user agents, headers, and URLs; its case studies examine fingerprint leakage and Java--JavaScript bridge risks~\cite{tiwari2022webviewfingerprinting}. Tracking Without Borders combines Java and JavaScript analysis with runtime and network observation, examining injected information and relationships between application permissions and WebView access~\cite{weerasekara2025tracking}. Cross-Boundary Mobile Tracking jointly observes Java calls and JavaScript execution inside WebViews to trace information diffusion and tracking across their boundary~\cite{datta2026crossboundary}. Thus, observing both application and WebView contexts is already an established approach.

\hg examines the semantic compatibility of associated environment observations under explicit applicability conditions. Memory, timezone, and geometry comparisons investigate additional device context and the interpretation of legitimate system or layout changes; unavailable evidence limits assessment. Host geometry remains a separate study, unintegrated into \full. The evidence does not validate every pairwise relation among the three views, and \full also contains single-field and within-view checks. Neither Native nor Host is a trusted root.

We have not compared these systems directly under a unified protocol and claim no empirical superiority. Our focus is the conditional evidentiary role of semantic references: when they expose report manipulation, how normal changes affect that interpretation, and where missing or compatible observations leave integrity unresolved.
