\section{HybridGuard}
\label{sec:method}

It preserves evidence states and constructs detectors under normal-alarm and coverage constraints; frozen App and App--browser models then evaluate current inputs. \subsection{Provenance-Bound Observation Collection}
Comparison requires associating values with the execution and collection context they describe. Under the contracts in Section~\ref{sec:setting}, Native, Host, and App Web observations retain values and field states. Original records, receipts, and association metadata support source tracing and validity checks.

Current collection intervals and stability information support applicable checks. In the geometry study, Host-before/after observations surround the Web snapshot within one collection; they are not attack-before and recovery-after records. Operation labels, experimental phases, and other pre-intervention or restoration records do not enter a current prediction.

Valid linkage to the external Browser forms paired observations; incomplete collection preserves App-only data without inventing a Browser vector.

\subsection{State-Aware Semantic Consistency}
An executable check combines operands, source and validity requirements, measurement interpretation, applicability conditions, and a trigger. Units, coarse reporting, and time context are handled according to the relevant API semantics. For a relation-conflict check, usable and applicable evidence violating $C_j$ triggers $r_j(x)$. The pool also contains single-field conditions, within-view relations, and admitted polarities; these are not all negations of $C_j$.

For current observation $x$, $r_j(x)\in\{\hgstate{T},\hgstate{F},\hgstate{U},\hgstate{FAILED}\}$. An empty selected set has its own status. Otherwise, the detector validates inputs required by selected checks: relevant execution or association failures yield \hgstate{FAILED} before considering triggers. Without such failure, any \hgstate{T} yields an alert; a nonempty set of all \hgstate{F} yields definite no-alert; remaining unresolved cases yield \hgstate{U}. Thus \hgstate{T} can coexist with another condition's \hgstate{U}, but cannot override \hgstate{FAILED}. Ordinary missing or inapplicable operands remain \hgstate{U}, not \hgstate{F}; unselected-field problems do not independently fail the detector.

\subsection{Cross-Layer Integrity Relations}
\paragraph{Native--Web memory.}
Native memory supplies device context through an upper envelope on the Web report. Both operands must be observed, finite, positive GiB values from the same bound App record, with $m_{\mathrm{native}}\geq0.25$. On these valid, applicable inputs, the trigger is
\begin{equation}
 r_{\mathrm{mem}}(x)=\hgstate{T}\Longleftrightarrow
 m_{\mathrm{web}}>2^{\lceil\log_2 m_{\mathrm{native}}\rceil}.
\label{eq:memory}
\end{equation}
The power-of-two envelope accommodates coarse reporting and permits lower Web exposures. It detects upward violations of this envelope; downward, within-envelope, or coordinated reports may remain compatible. Unusable measured operands yield \hgstate{U}; binding failures retain \hgstate{FAILED}. The fixed Web-only comparator is $m_{\mathrm{web}}>8$ GiB.

\paragraph{Native--Web timezone.}
The Native IANA zone supplies context for interpreting a Web offset. For time-dependent zones, the current device collection interval and fixed timezone database 2026c determine the effective UTC offset. The check compares its negative with Web \texttt{getTimezoneOffset}, using UTC-minus-local minutes. Supported fixed-offset IDs can be evaluated without a date when consistent with the observed Native standard offset. The comparison concerns effective offsets, allowing different names with the same offset.

Missing reliable intervals for time-dependent zones, ambiguous transition intervals, or unusable measurement evidence yield \hgstate{U}; zero and minus one are valid values. Database or association failures follow the \hgstate{FAILED} policy. A normal system-zone change can remain compatible when the measured offsets move together, while a local Web override can violate the relation. Collection timing and applicability still bound this interpretation.

\paragraph{Host--Web geometry.}
The containing View supplies geometric context outside the webpage's own measurements. For either axis, $P$ is the CSS visual-viewport size multiplied by device-pixel ratio and viewport scale; the local scalar $H_{\mathrm{view}}$ is the Host View size minus its own padding. The check triggers if either axis satisfies
\[
\begin{aligned}
P &> H_{\mathrm{view}}+\epsilon,\\
\epsilon &= 2+4\cdot2^{-23}\max(|P|,|H_{\mathrm{view}}|,1)\quad\text{pixels}.
\end{aligned}
\]
Snapshot binding and Host stability before and after that Web snapshot are prerequisites. Stability is assessed independently of Host--Web agreement, preserving stable contradictions as evidence. Valid dimensions, pixel ratio, and scale must be finite and positive. The implemented domain requires an attached, visible View, zero padding, and an identity View transform; outside-domain measurements yield \hgstate{U}, while binding failures yield \hgstate{FAILED}. The tolerance is an engineering choice, not a platform guarantee. This specialist check remains separate from \full and its candidate pool.

\subsection{Constrained Detector Construction}
Checks need detection information, normal-data availability, and bounded alarm and inconclusive-output costs. Maximizing controlled detections alone does not enforce these requirements. The App pool comprises 50 base templates and three fixed relations: Native memory, Native timezone, and same-Web viewport. Training-side numeric encoding and threshold expansion produce 65/65/56 atoms before admission, which considers admissible polarities. Historical evaluation records do not supply thresholds.

For selected singleton-OR clauses $S$, the sparse stage uses
\begin{equation}
 J(S)=\frac{1}{K}\sum_{k=1}^{K}\overline{d}_k(S)-0.005\,C(S),
\label{eq:selection}
\end{equation}
where $K=14$. Each $\overline{d}_k$ averages whole-detector detections over effective positions within each training environment, then equally across environments. Complexity $C(S)$ counts clauses plus literal occurrences, distinct from compatibility relations $C_j$. Greedy improving additions, the best feasible prefix, and backward pruning constitute a heuristic without global-optimality guarantees.

Constraints allow at most eight singleton OR clauses, complexity 16, two conditions per registered family, and no opposite polarities of one atom. Controlled and historical training-normal alarm budgets are 8/168 and 31/630. Historical-normal candidate assessability and final definite-output coverage must each reach 90\%; controlled coverage must reach 80\% per phase. Fits disallow execution failures and have a 60-second deadline. Appendix~\ref{sec:appendix} details training-side admission.

Retention starts from each configuration's own sparse solution and preserves existing training detections. Additions increase semantic coverage; same-group swaps use registered higher-quality alternatives and additionally forbid new controlled-normal alarms or losses of definite controlled outputs. All proposals remain feasible. Retention does not continue optimizing Equation~\ref{eq:selection}. Evaluation uses fixed saved retention models, without selecting stages or configurations per result cell.

\subsection{Additional Observation Surface: External Browser}
The extension tests whether a separate Web execution adds evidence beyond App observations. It is an optional evaluation mode, not a sequential fallback. The retained cross-endpoint extension, \full+C1, combines \full with condition C1, which triggers on unequal, validly linked App Web and Browser offsets using the same Web sign convention.

Both operands require observed status, observed-value quality, and finite numeric, non-Boolean values; zero and minus one are valid. Unavailable or inapplicable operands yield \hgstate{U}; association failures retain \hgstate{FAILED} precedence. C1 has no timestamp gate and does not inherit Native timezone interval handling, leaving asynchronous normal setting changes unresolved.

Construction enumerates no addition, C1, language condition C2, and C1+C2 on the frozen App base. Normal-alarm budgets are 31/630, 0/12, and 1/34 for historical training, pilot, and matched normals, respectively, with 90\% definite outputs per normal group and 90\% historical candidate assessability. C2 alarms on two matched normal preference changes; C1+C2 also has only 566/630 definite historical training outputs. Neither satisfies the constraints. This selects an increment without retraining a joint classifier over all fields. Original App-benchmark positions lack contemporaneous Browser counterparts, so paired evaluation remains separate.
