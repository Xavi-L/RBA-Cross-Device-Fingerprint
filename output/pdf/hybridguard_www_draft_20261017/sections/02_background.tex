\section{Setting and Threat Model}
\label{sec:setting}
\subsection{Observation Surfaces}
We distinguish four surfaces. \emph{Android Native} exposes system and hardware-related measurements, such as memory and the system timezone. The \emph{WebView host} controls the container, provider, bridge, and layout context. The \emph{App Web runtime} exposes JavaScript APIs inside that WebView. An \emph{external browser} runs a separate Web probe outside the application. Android documentation describes the host's ability to configure WebView behavior and the bridge between native code and JavaScript~\cite{android2026webview}; this arrangement does not make the native side an attested root of trust.

The App contract, \appfp, comprises 84 Native, 26 host, and 67 in-app Web fields. A companion \browserfp contract contains 67 external-browser fields. A complete linked observation can be represented as \pairedfp. These names describe measurement contracts, not numbers of independently informative features or inputs used by every detector. In particular, the evaluated App candidate pool does not contain the new host-geometry check, and the retained browser extension uses one timezone relation rather than all 244 fields.

\subsection{Adversary and Normal Behavior}
The tested adversary changes selected client-visible reports through controlled tools, browser emulation, or runtime overrides. The benchmark includes changes to resource reports, user agent and platform, timezone, screen metrics, language and plugin surfaces, WebGL identifiers, and webdriver exposure. The attacker need not change the physical device. The evaluation labels require an observed effect at the target surface: an attempted operation with no measurable effect is retained separately.

A useful reference is a second observation that the tested modification has not changed in the same way. We do not assume that an adversary can never manipulate Native or host observations. An attacker able to coordinate every compared surface, modify the collector, or compromise the collection backend may evade consistency checks. The study neither proves resistance to that attacker nor establishes that independently launched endpoints are statistically or administratively independent.

Normal behavior includes changes to system timezone or language, display orientation, and application layout. APIs can also reduce precision, lack support, return different units, or expose container-specific state. Such variation must be represented in applicability checks and normal controls rather than labeled malicious because two values differ. A manipulation alert indicates a violated tested condition, not a finding of fraud, account takeover, or malicious user intent.

\subsection{Evidence Units and Decision States}
The unit of evaluation is a saved \emph{record position}, or an App--browser paired position where required, with an independently assigned experiment role. Counts of repeated operations are not counts of independent devices. A detector returns alert (\hgstate{T}), no alert (\hgstate{F}), or unknown (\hgstate{U}); execution failure and an empty model are separate outcomes. An unavailable operand may prevent a conclusion, and a no-alert result establishes only that the selected conditions did not trigger. Ground-truth experiment roles and operation records are used for evaluation, not as detector inputs.
