\subsection{Saved Model Identities}\label{app:1}}

App configurations 01, 02, and 03 hold out emulator API 29, 30, and 36, respectively. A\_\allowbreak{}NO\_\allowbreak{}MTC\_\allowbreak{}CAP, A\_\allowbreak{}APP\_\allowbreak{}WEB\_\allowbreak{}ONLY, A\_\allowbreak{}NO\_\allowbreak{}MEMORY\_\allowbreak{}REL, and A\_\allowbreak{}NO\_\allowbreak{}TIMEZONE\_\allowbreak{}REL are refitted alternatives. The candidate-state tree uses scikit-learn 1.7.2, splitter=best, random\_\allowbreak{}state=20261006, no class-weight override, and a positive-class probability threshold of 0.5. Its admitted pools contain 63, 63, and 54 atoms, each encoded by three state indicators; these are smaller than the pre-admission pools. Fifteen positions in each controlled held-out set and 73/891 MTC records have an unknown candidate. A fitted path need not use that candidate, so binary predictions do not imply complete observation.

\hypertarget{app:2}{%
\subsection{Candidate Admission and Extension Choice}\label{app:2}}

Threshold expansion uses training-only quantiles 0.25, 0.5, and 0.75. Candidate support requires at least three complete true/false triplets and at least two triggered modification triplets in at least one bundle/environment, alongside normal assessability. For Browser extension, feasible choices among none, C1, C2, and C1+C2 are ranked by the equal mean detection ratio across App timezone, App language, Browser timezone, and Browser language. Ties prefer fewer additions and then a fixed set order. This ranking is part of development-side selection.

The fixed timezone comparator triggers above −480 minutes; the old Web-height comparator triggers above 710 CSS pixels. Native timezone uses effective offsets under the fixed implementation database. Geometry follows Section~\ref{sec:3-3}. C1 requires both status and quality markers, accepts finite numeric offsets including zero and minus one, and applies no timestamp gate.

\hypertarget{app:4}{%
\subsection{Public Dataset and Verification Scope}\label{app:4}}

The Cross-View Consistency Dataset v1.0 contains 378 controlled App, 72 memory, 36 timezone, 72 Host-geometry, 60 linked-Browser, and 891 historical MTC observations. The first four groups form 558 App177 records; the last two form 951 Paired244 records. Of the 618 experimental observations, 170 are labeled modified, 442 normal\_\allowbreak{}control, and six no\_\allowbreak{}effect. Labels are reconciled against saved collection and intervention evidence, separately from saved detector outputs. The six no-effect memory operations remain outside that study's 18-modification and 48-normal denominators. MTC records remain unlabeled; their 630/144/117 historical partition retains its development exposure.

Four JSONL files provide measurements, metadata, annotations, and relationships, joined by random release identifiers. Record-level links preserve 206 experiment triplets and 951 App--Browser endpoint associations. The field catalogue documents 177 App slots and 67 additional Browser slots. Original field structure is complete for 1,506 records; three MTC records each lack five original fields. Collection availability, original absence, and privacy suppression are represented separately. Recorded geometry supplements accompany 72 observations.

The release includes a dataset card, schema, field catalogue, statistics, manifest, and standalone Python tools. Running \texttt{python3 validate.py -{}-root .} checks schema, joins, label consistency, missingness, relationships, and descriptive statistics; \texttt{python3 load\_example.py -{}-data .} demonstrates loading. Data and designated documentation are licensed under CC BY 4.0; this grant excludes the two scripts, whose software-license status is unspecified. The public artifact supports reproduction of the released data projection and its statistics. It suppresses selected identifying or decision-relevant values and omits raw logs and the full detector implementation. Detector-outcome annotations retain the original archived predictions.

Manuscript checks reconcile saved state partitions, recipe-level counts, experiment identifiers, and file hashes. Implementation tests cover decision states and binding failures.

\hypertarget{app:geometry-tolerance}{%
\subsection{Host Geometry Tolerance and Post Hoc Sensitivity}\label{app:geometry-tolerance}}

The standalone Host geometry check uses the frozen tolerance
\[
\epsilon(P,H_{\mathrm{view}})
=2+4\cdot 2^{-23}\max(|P|,|H_{\mathrm{view}}|,1)
\quad\text{pixels}.
\]
The constant 2 allocates one pixel to each of two layout edges as a study-specific quantization assumption. The factor \(2^{-23}\) is the float32 precision scale, and 4 is a fixed coefficient for the numerical margin. This reference scale sets the budget; the saved evaluator computes the comparison using Python \texttt{float} arithmetic. Operation-level error bounds for the rendering chain and their transfer across WebView implementations remain to be established. The specification was frozen during development after six engineering-smoke observations and before the formal v15 batch.

We perform a \emph{post hoc sensitivity analysis} using only the 72 formal v15 observations saved in \path|deliverables/screen_geometry_observation_v1/predictions.jsonl.gz|. The 66 normal records satisfy \texttt{normal\_\allowbreak{}basis.supported}; the six effective interventions satisfy \texttt{observable\_\allowbreak{}intervention}. These are repeated observations from three emulator environments. Keeping the saved applicability, U/FAILED states, and subset labels fixed, we use each record's current Web operands and measured Host dimensions. We preserve the implementation's multiplication order: first DPR times \texttt{visualViewport.scale}, then the CSS dimension times that product. Each axis uses a strict \(>\) comparison, and axis outcomes are combined by the original OR rule. With \(M=\max(|P|,|H_{\mathrm{view}}|,1)\), Table~\ref{tab:geometry-sensitivity} reports the outcomes.

For each record, take the maximum of \(P-H_{\mathrm{view}}\) over width and height. Its largest normal value is approximately \(2.000038\) pixels; effective interventions span \(475.381\)--\(664.381\) pixels. Removing the relative term therefore changes decisions for normal observations near the 2-pixel boundary. Coefficients 1, 2, 4, and 8 yield identical decisions on all 72 records. We retain the original frozen coefficient 4, with the fixed 3-pixel row used only as a sensitivity comparator. This post hoc analysis leaves coefficient choice, parameter optimality, and performance against small near-boundary interventions unresolved; independent validation of a revised tolerance requires fresh observations.
