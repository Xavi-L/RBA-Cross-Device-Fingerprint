# 剩余研究与补数据的实施条件

> 历史 v2 计划，已由用户最新资源约束替代。用户明确没有补采机会；以下 25 项现已完成终局处置，不再作为待研究／补采任务。当前结果见 [v3 研究收尾报告](../mtc_closed_resource_20260922/REPORT.md)。以下正文保留当时计划语义。

本批第一阶段已完成。剩余 17 项研究和 8 项补数据继续留在执行台账内；本文件是后续工作规范，不是已执行结果。开发集已经在 P3/P4 及本批观察过，后续不得称其为新的盲测集。保留验证集继续封存。

## 研究顺序

| 顺序 | 规则条目 | 先做什么 | 可以晋级的条件 |
|---|---|---|---|
| 1：身份可比性 | NW-001、NVW-001、NW-004 | 分开 App UA、system HTTP agent、Browser UA 的语义；冻结型号解析、别名和 platform/ABI 可比较范围 | 每个别名/映射有来源；缺型号、简化 UA、未知 platform 不判冲突；按发现/开发分组保留全部匹配、反例、未知与不适用 |
| 2：显示与内存 | NW-003、OFFDER-DISPLAY-001、NW-008、OFFDER-MEMORY-001；包含 TOL-002/003 的容错要求 | 审计显示口径、方向、窗口/缩放及内存分桶；有不同假设时预先列出有限候选 | 在发现集定义归一/容差，开发集检验；不为覆盖开发反例反复放宽，不沿用 10% 或 3–4GB；无法从现字段解释的条件保留未知或转待补数据 |
| 3：硬件与渲染 | NW-005、PHYS-001、PHYS-002、OFFDER-EMULATOR-001 | 对硬件别名、GPU 族、ANGLE/软件回退做来源审计，分清环境描述和矛盾判断 | 未知/屏蔽 renderer 不判冲突；真实虚拟环境需有独立身份依据；虚拟设备不直接等于攻击 |
| 4：能力与 API | CORE-003、OFFDER-SENSOR-001、OFFDER-PLUGIN-001 | 区分能力缺失、采集不可用和字段自洽；核对 plugin API 默认回退 | 不使用固定传感器数定义真实设备；P3 传感器自洽不重复算独立支持；插件差异有版本/实现依据 |
| 5：缺失与组合 | CORE-001、SCENE-002、SCENE-003 | 明确缺失原因，再审计组成关系；场景组合后于组成规则 | 不把源不可用、宿主缺失直接当重放；不使用未实现的耗时阈值；共享证据去重，组合本身需独立检验 |

以上恰好覆盖 17 项，不以规则数量或旧效果为目标。相近的经验条目与官方派生条目可以共用比较实现，但来源、适用性和数据依赖仍要分别记录。

每个研究家族按以下步骤留下独立版本：

1. 看数据前列出有限语义假设、需要的字段、不可比较条件、统计单位和选择标准。已经接触过的开发资料如实记录。
2. 只通过 `load_split_records` 读取发现集。输出组级支持、反例、不可用原因和覆盖；同组重复不能增加独立支持票。
3. 冻结候选表达式、依赖、参数与例外后运行开发集。所有候选和负结果保留；修改候选必须新建版本并记录开发暴露，不能将重跑称作独立验证。
4. 满足预先定义的条件才接入下一版目录；不满足则保留研究、降为上下文、合并或停用。没有已核验攻击标签时，只报告关系行为与覆盖。
5. 覆盖正例、反例、缺失、哨兵、不适用、数值边界与输入遮蔽；检索卡参数、Verifier 重算和 trace 同时通过。继续比较未修改的旧检查，避免无意语义变化。

## 需要补数据的 8 项

| 条目 | 当前缺口 | 最小新增证据与验收 |
|---|---|---|
| PHYS-003 | 无规范的重复耗时及运行条件 | 同一可信实例、单调/真实时间标记、预热与挑战版本、负载/前后台条件、重复观测；采样协议先冻结。现有 50/800ms 不能复用 |
| PHYS-004 | 温度长期固定没有时间依据 | 同实例与时间绑定的温度序列，记录电量、充电、负载及观测间隔；普通温度值或同型号多条不能替代序列 |
| OFFDER-BATTERY-001 | 电量/温度/电压/充电时间关系 | 与 PHYS-004 共用采样包；判定时间窗和最少观测依据先确定，证据不足仍未评估 |
| OFFDER-PLAY-001 | 无服务端验证 verdict | 新版采集包记录真实请求与服务端验证事实，绑定同次样本；不支持、失败、超时保留为独立状态 |
| OFFDER-PLAY-002 | 无请求绑定及防重放事实 | 与上项联动，按当前官方协议实现与验证请求绑定/时效；客户端自报文本不替代服务端验证 |
| OFFDER-KEY-001 | 无可验证的硬件证明材料 | 新版协议取得挑战、证明材料及服务端验证结果，绑定样本；缺能力与验证失败明确分开 |
| OFFDER-BOOT-001 | 构建字段不能代替 Verified Boot 证明 | 与硬件证明联动，获得有来源绑定的 boot/locked 状态；授权开发构建或自定义 ROM 不直接当攻击 |
| OFFDER-WEBSEC-001 | 设置与实际加载页面没有 Origin 联合事实 | 记录同次导航的 scheme、host 与版本化信任策略，能关联所用 WebView 实例；设置开启不直接判危险 |

这些是新增数据合同，不能回填到现有冻结 244 字段中冒充旧观测。时间序列与完整性/导航扩展应各用新版本旁路记录及关联信息，不重启已退役的本机后端或 ngrok。实际补采须先完成新采集方案和可用环境，再执行；本批未开展补采。
