使用同一 FeatureApp 1.6.5、versionCode 12，以及原攻击配置的声明参数。新增的是原始 webdriver 观测记录及本地采集编排。攻击侧仓库保持原样。执行回执、原始字段效果、声明字段恢复均通过，才将该干预位置标为监督样本。标签仅表示已验证的指定受控干预有无，不代表广义攻击真值或自动化引擎内部状态。

两组分别在自己的候选池内运行原 GREEDY 初始化和 R_KEEP_V1，保留原支持门槛、80% 阶段覆盖门槛、OP05 对照预算、6 条规则与复杂度上限。语言长度旧条件仍在两组候选池内；新组增加首项关系并删除旧 webdriver 条件。数值编码器仅从本折训练数据拟合，不强制新条件入选。模型保存并重新加载后才读取留出输入，预测文件关闭后才关联留出标签。基础输入中仍有 45 个 CAT:OFFDER-TOUCH-001 的 U 单元格，均原样保留；最终所选模型的决策覆盖为 100%，不表示所有输入字段都没有未知值。

**为何得分持平、覆盖却交换。** 保存的输入和训练记录给出了三项直接证据，详见 [SELECTION_DIAGNOSIS.json](SELECTION_DIAGNOSIS.json)。该诊断仅分析已有字段、训练轨迹和预测，没有额外 fit 或模型 predict。

1. 主样本的新版 webdriver 条件为 36 T、342 F；旧条件与新版在全部 378 条上的状态一致。原始观测使本轮 false 有明确来源，旧混合数据的未知值阻碍没有出现在这个适用域内。
2. 语言首项条件为 9 T、369 F。9 条触发均已被旧「语言列表长度 > 1」覆盖；后者在此队列触发 18 条。三个训练折中，新语言正条件各有 6 个触发三联样本、新 webdriver 正条件各有 24 个，均满足原有准入门槛，未因未知值或支持不足被排除。
3. 保存的 GREEDY 轨迹显示：同分时按候选 ID 字典序选择。旧 webdriver 的 `CONTROL:...` ID 排在部分其他条件之前，替换后的 `RSR-WEBDRIVER-STATE-v1` 排在之后。三个训练折均出现相同的等分取舍；新组先填入时区、内存、旧语言长度和屏幕像素比，达到 6 条上限。R_KEEP 只追加规则，三个折均以 `ORIGINAL_CLAUSE_LIMIT_REACHED` 停止，未改变初始化模型。

两组共同保留的五条条件为 NW-006 桌面/脚本 UA 痕迹、MIME 数量 > 0、时区偏移 > -480、deviceMemory > 2、语言列表长度 > 1；BASE 的第六条是旧 webdriver=true，新组的第六条是 devicePixelRatio > 2.625。这些是当前受控训练材料中学到的条件，不是正常 App 的普遍语义定律。新版 webdriver 候选未入选，不能把本次 webdriver 漏检归因于新版条件在样本上判错。

原始记录分为 378 条主成员、46 条辅助材料、23 条 API 28 边界材料及 9 条未纳入主比较的原配置采集序列残留。`RAW_ROLE_INDEX.json` 的 `EXCLUDED_INCOMPLETE_OR_FAILED_ORIGINAL_TRIPLET` 是这一组的粗粒度标记，不能理解为每组三联样本都失败：API 29 原时区第 1 组三联样本自身通过，但第 2 轮失败、该配置未完成三轮，所以原第 1 组也未纳入主比较。该配置统一使用事先登记的修订采集来源，原记录保留供复核。

首次扩展的三个时区失败分别发生于 API 36/30 第 1 轮和 API 29 第 2 轮。原 runner 把完整运行时对象差异判为撤销失败；日志显示时区恢复但视口高度变化。本地修订要求同进程的 CDP 相关锚点恢复，并由独立 clean_post 核查所有声明字段恢复。API 36 后续还发生一次旧 Activity 复用、没有新 payload 的失败，另行登记强制新进程启动后完成采集。原失败、原 runner、两次修订及全部日志均保留；没有事后放宽数值容差。见 [撤销观测修订](ROLLBACK_PROTOCOL_AMENDMENT.md) 与 [新 Activity 启动修订](FRESH_LAUNCH_AMENDMENT.md)。

API 28/WebView 66 的 webdriver API 缺失仍保留为 U；语言攻击工具还因缺少 Object.fromEntries 失败，未进入主比较。不能用本轮三个支持环境的结果覆盖该边界。三个环境在同一 Mac、ARM 模拟器和采集 App 上运行，只有两个 WebView 版本；材料准备阶段已查看完整数据。这不构成独立确认，不支持正常真机 App 总体误报率、全 Android 兼容性或真实攻击泛化结论。

**执行核查与后续。** 已完成 12/12 次真实 fit、756/756 次留出预测，12 个模型均 FITTED，无自动重试、追加调参或全开发集拟合。累计预算由 177/200 变为 **189/200，剩余 11 次**；最新结算见 [prepared/EXECUTION.json](prepared/EXECUTION.json)，旧实验账本保留原历史数值。核心适配器 23 项、采集/执行边界 9 项测试及 CDP 撤销重点测试通过；[准入核查](ADMISSION_REVIEW.json) 和 [结果核查](RESULT_REVIEW.json) 均 PASS。

目前结论是：重训所需的新原始观测和三环境对照流程已经打通；本轮未取得净检出提升，也未消除逐配置退化。下一步应先处理同分候选排序和规则容量取舍，明确是否要求保留 webdriver 覆盖，再另行冻结比较方案；不应直接把当前新模型当作已验证的替换版本。任何新拟合需先核对剩余 11 次预算。本轮到完成结果报告为止，不自动执行下一轮训练；Git 交付按后续明确授权执行。
