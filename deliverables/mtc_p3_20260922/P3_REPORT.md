## 输入、范围与验收

## 事前筛选与来源边界

沿用 P2 全局经验支持下限：发现／开发至少 30／10 个可评估组和 3／2 个厂商。限定范围门槛未用来挽救失败候选。增加事前固定的工程筛选线：两集组级关系一致比例均至少 95%。这只是研究优先级筛选，不是统计显著性、检测效果或规则必然成立的证明；不是根据旧效果选择的目标。

组内有任何反例即记反例；否则有未知即记未知；否则存在适用的一致记录才记一致。分母仅为 MATCH + COUNTEREXAMPLE。条件传感器 `has=false` 记不适用，不当作“通过”。已知 deviceMemory／cores 零哨兵、非有限数、无效类型、解析失败和明确不可用状态记 UNKNOWN。

屏幕短边模板只允许事前固定的 **1 CSS px** 残差：App reported display 短边 / DPR 对 Web reported screen 短边。没有拟合系数、分位数、宽容区间或按开发结果调整阈值。发现入选清单在读取开发特征前持久化；开发再好的结果也不能救活发现落选模板。

官方文档只提供字段语义；项目派生表达式、条件和研究筛选仍单独标注。源自同一采集器赋值的关系单列 `collector_derived_consistency`。引用官方资料不会把经验选择变成官方结论。16 个一手资料及独立预审见 [SEMANTIC_REVIEW.md](SEMANTIC_REVIEW.md)。

## 旧规则结论的重新评估

- **CORE-002：** 发现 12、开发 2 条触发全因传感器数 1–9，JSBridge 均为 true。不能把旧的 `<10` 条件继续当作这些未标注设备的攻击证据；转为能力／上下文解释，桥接分支单独审查。
- **OFFDER-WEBVIEW-001：** 发现 32、开发 9 条违反全来自包版本首段与 UA Chromium major 的命名空间不一致。41 条 default/settings/runtime UA 全部相同；华为、荣耀及部分 smartisan 的包版本首段并不表示 Chromium major。旧的无条件等值关系不进入新版风险解释，也不能按包名粗暴豁免。
- 其余旧关系即使没有观察到违反，也不能据此证明检测能力或继续沿用旧效果。短路跳过、未知、不可执行项全部保留。

完整旧规则分母、源值诊断和处置表见 [LEGACY_BASELINE.md](LEGACY_BASELINE.md)。历史引擎及规则配置保持原样，修订处置作为 P4 输入，避免污染“旧规则原样重放”基线。

## 语义约束与落选结果

14 个语义研究约束包括：两容器 `pixelDepth=colorDepth`、同一次 MemoryInfo `avail<=total`、10 个 `has_sensor=true → type in list`，以及尊重 UA reduction 的 OS 对照。它们仍有项目范围假设，并经过本轮经验筛选，不是官方直接攻击判决。

Browser OS 模板将 Chrome>=107 且 Android10 token 视为可能简化 UA，不再作为真实 OS 相等证据：发现 133 组、开发 33 组为不适用，另有 9／3 组未知。剩余发现 464/468 组一致、4 组反例；开发 106/106 一致。4 条反例原值均保留（3 条旧 MQQBrowser UA、1 条定制 MIUI UA），未推断攻击，也没有据其新增白名单。即使设备恰好运行 Android10，简化 token 也不会得到一致票。

| 没有晋级的无条件经验等式 | 发现反例组／可评估组 | 开发反例组／可评估组 |
|---|---:|---:|
| timezone ID 字符串相同 | 32/590 | 5/138 |
| languages 有序列表相同 | 140/610 | 30/142 |
| platform 字符串相同 | 361/610 | 82/142 |
| deviceMemory 相同 | 40/542 | 6/132 |
| 跨端 colorDepth 相同 | 48/610 | 8/142 |

另 10 项从语义预审即限定为描述性诊断：两端 GPU vendor/renderer、Canvas、Audio hash/sampleRate、字体 hash、plugin/MIME hash，以及两个不考虑简化 UA 的 Native–Web OS 等式。即使有高一致比例也不晋级为通用严格等值规则。例如 Canvas 反例发现 529/610 组、开发 126/142 组；Audio hash 反例 429/602 与 101/142 组。plugin/MIME hash 本批全为空；空枚举和 API 缺失回退无法可靠区分，全部 UNKNOWN，不能把空串相等当支持。

另外明确排除：Native RAM 与 deviceMemory 精确相等、Native raw timezone 与 Web offset 简单反号、同一 canvas 先 WebGL1 后 WebGL2 得到 false 的能力判断。后者存在采集器探测缺陷，当前未改采集器或回写旧数据。没有专门重复采样，不能声称 hash 的长期或同设备稳定性。

## 纠错与验证透明性

第一次执行发现了实现格式错误：采集器 `os_version` 实际为 `Android <release>`，初始版本解析器只接收开头数字，导致 3 个 OS 模板被错记 UNKNOWN。原输出保留在 `artifacts/mtc_p3_discovery_20260922/`，`RUN_STATUS.json` 明确作废；采用修正版 **v2.0.1** 复跑到 **`artifacts/mtc_p3_discovery_20260922_r2/`**。

只修复可由既有采集器源码确定的格式兼容，没有改 45 个模板的表达式、依赖、范围、支持度或筛选阈值。逐项比较证实只有 3 个 OS 模板的结果变化，其他 42 项完全一致。由于已经看过首轮开发输出，修正版协议明确 `prior_p3_development_exposure=true`，不声称开发集是全新盲测。保留集从未因这次纠错解锁。

44 项测试涵盖两来源原样基线、主代表与双端绑定、未选源行不解码、控制信息隔离、未知/哨兵/数值与布尔边界、真实 Native OS 格式、简化 UA、screen 容差、sensor 单向条件、组级分母、发现名单冻结和开发不可补选。直接产物检查另确认候选依赖全部属于 paired244 目录、全部反例保留、目录无风险权重。见 [VALIDATION.json](VALIDATION.json)。
