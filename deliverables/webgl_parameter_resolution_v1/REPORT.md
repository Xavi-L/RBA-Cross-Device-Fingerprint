## 第一步：错误出现在哪里

在 API 36 / WebView 134.0.6998.135 上，host 和 SwiftShader 各执行两轮正常—攻击—恢复，
共 12 次 App 采集。每次另外检查空白页与正式采集页，共保存 96 个逐操作诊断 context 记录。

host WebGL2 在空白页和采集页中都表现为：`getContext` 返回后，第一次调用 `getError` 就能读到 1280。
这时尚未调用 `isContextLost`、启用 debug renderer 扩展或进行 vendor/renderer 参数查询。
正常、攻击、恢复三个阶段均如此。将错误检查推迟到扩展调用之后，会在那个位置读到同一错误，
因此上一轮“扩展后 preflight 有错误”不足以归因于扩展。

12 个 host WebGL2 `error_first` 记录均在创建后出现该错误，后续操作未出现新错误。
48 个 WebGL1 诊断 context 记录均无错误；软件渲染路径的 48 个诊断 context 记录也均无错误。
这些记录来自 12 次采集，不是 96 台独立设备。

定位结论：错误在本环境的 WebGL2 初始化路径上已可见，发生在观测器的参数查询之前。
具体是 WebView、ANGLE、模拟器图形实现还是驱动的哪段代码导致，仍未确定。
证据见 [LOCALIZATION.json](LOCALIZATION.json)。诊断过程的主动清空错误不能用来覆盖旧判定结果。

## 第二步：固定一个独立 WebGL1 候选

冻结 `webgl1-parameter-equivalence-candidate-v1`，实现于
[webgl1_parameter_candidate.py](../../hybridguard_agent/research/webgl1_parameter_candidate.py)。
它复用未修改的 v1 envelope、外部会话绑定和质量检查，只读取通过验证的 WebGL1 子结果：

- T：同一参数的数字前后值稳定，但等价字符串参数得到不同值。
- F：WebGL1 的 vendor、renderer 查询均一致且质量检查通过。
- U：WebGL1、控制项、原始查询、版本或会话绑定缺失/不合格，或者数字前后读值漂移。

WebGL2 和完整 v1 结果作为诊断保留，既不替代 WebGL1 结果，也不提供新候选的告警。
F 只表示这项 WebGL1 冲突未被观察到。**仅修改 WebGL2 的攻击可能不会触发这个候选**；
该边界已用合成测试明确，不能把新候选宣传为覆盖全部 WebGL 篡改。

候选合同在下一阶段采集启动之前冻结，见 [CANDIDATE_CONTRACT.json](CANDIDATE_CONTRACT.json)。
收窄范围来自已暴露的开发证据，因此后续结果仍属于开发验证，不是独立确认。
