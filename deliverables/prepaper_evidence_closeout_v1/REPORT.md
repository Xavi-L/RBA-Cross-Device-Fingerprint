## 4. 一次离线成本测量

### 范围与计时口径

在本机Darwin 24.6.0 arm64、Python3.13.5、numpy2.5.3、sklearn1.7.2、scipy1.18.1环境执行，详见[TIMING_FREEZE](timing/TIMING_FREEZE.json)。GC默认开启；`perf_counter_ns`使用单调 `mach_absolute_time()`，记录的时钟分辨率约41.7ns。该分辨率不是测量精度保证。

固定同一批60成员（18先导+42匹配）和固定顺序，21模型各阶段一次预热、10遍；共148个阶段组、1,480个记录批次，含预热1,628项输出检查全部一致。模型加载每批1项，其他每批60项。CSV保存10个批次的均摊值与其P95；**P95是批次均摊分布，不是单请求尾延迟**。没有逐请求计时，没有从951中按预测成功过滤出“100%端到端可用”子集。

| 字段 | 起止范围 |
|---|---|
| load_parse_validate | 读取本地模型/预处理JSON、解析并校验；规则包括基础文件及条件摘要、身份校验。热文件系统中的重复读取，不是OS冷启动。 |
| loaded_raw_adaptation | 已在内存的App/Browser归档对象及provenance，经过原App原子/内部关系编译、配对绑定与固定字段投影。共享准备中位数7.6255ms/条，批次均摊P95 7.8563ms。 |
| model_input_prepare | 已适配测量到模型输入：规则的冻结编码与所选C1/C2；树的视图测量、关系（REL）、冻结预处理及投影。 |
| prepared_inference | 已准备输入上的原规则判定+扩展组合，或JSON树遍历。不把单独OR称完整paired244推理；规则入口还保留原模型身份等开销。 |
| original_current_interface | 原公开当前输入接口完整调用。B2-C每次实际执行基础模型读取、摘要校验、预处理及条件；B3-A原接口从派生cells开始，其不执行的raw适配/C1/C2准备不能当作免费。 |
| cached_from_adapted | 本目录计时包装复用已加载对象，从已适配测量执行准备+判定；不改旧生产代码。 |
| loaded_raw_to_original / cached | 从已加载两端归档对象执行共享适配及对应路径；树关系准备已计入。仍不含raw文件读取/JSON解析、设备采集、上传和首次模块导入。 |

计时包含Python循环、函数调用、对象分配、冻结入口自身的计数/事件记录以及轻量包装计数；全调用profiling关闭，写入/网络审计钩子保留。日志文件写入与结果核验位于计时区间外。统一raw包装对单端树可能做多余App准备，因此不是单端实现的最优性能界限。加载、公开接口、raw包装是不同路径，不能把各列简单相加（公开规则接口自身已重复加载）。

缓存/分解路径先逐条与原公开入口及保存结果比较：21×60=1,260项，每项4路径，状态一致，树分数差<1e-14。证据：[等价结果](timing/equivalence.jsonl)、[原始计时](timing/batches.jsonl)、[运行账本](timing/EXECUTION.json)。
