# Android 5–7 HTTPS 兼容性复测包

- APK：`HybridGuard-FeatureCollector-1.6.4-mtc-https-debug.apk`
- 包名：`com.example.hybridguard.featureapp`
- 版本：`1.6.4-expanded-v2.2-mtc-https` / versionCode 11
- 最低系统：Android 5.0 / API 21；Android 4.4 不支持。
- 日期：2026-09-21
- 采集入口：`https://collect.crossdevicefingerprint.site`

## 本轮修改和部署

App177 上传、浏览器票据、配对查询及 Browser67 页面统一使用新域名。ECS 提供 ZeroSSL RSA 证书与静态页面，通过 ngrok 转发到原电脑后端，数据继续保存在电脑。

App 保留 1.6.3 已有的旧 Android TLS 修复和明确错误日志。没有修改指纹字段、177/67 口径或配对算法，也没有关闭证书验证。

实际 HTTPS 证书链经 USERTrust RSA 交叉签名。仅使用 AOSP Android 5.1.1、6.0、7.0 对应根证书的 TLS 1.2 握手分别验证通过；这不等于所有厂商浏览器或实际失败机型已验证。

## 复测顺序与成功标准

1. 先确认 readiness 为 `ready`，电脑后端和 ngrok 持续运行。
2. 安装本目录 APK，核对 versionCode 11，沿用现有自动化脚本的启动和权限处理流程。不要用调试参数将 endpoint 覆盖成旧域名。
3. 优先复测此前失败的 Android 5.1.1、红米 Note 4 / Android 6.0、荣耀 Note8 / Android 7.0，再扩大设备范围。
4. 让 App 完成 App177 与外部浏览器 Browser67；不要在刚启动浏览器或脚本刚结束时立即回收设备。
5. 由后台核对同一 App session / pair ID 的 `pair_status=completed`，才记为一条 paired244。仅安装、页面打开、App 上传或脚本通过不能算完整采集成功。

不要直接在浏览器手工打开域名首页来判断配对成功：采集页面需要由 App 携带有效票据启动，空首页不会生成完整配对。

Android 5.1.1 的全部失败原因尚无该版本日志确认。本次解决已发现的 HTTPS 信任路径问题，其他系统/API/浏览器错误继续依据新增日志分析，不声称全部旧设备失败均已修复。

## 失败时保留

从 App 启动至最终状态的完整 logcat、设备型号、Android 版本/API、系统时间、浏览器及 WebView 版本、App session / pair ID、浏览器证书或页面错误画面，以及是否经代理。区分 App HTTPS、浏览器页面 HTTPS、浏览器 API 上传、探针执行与配对等待阶段。

证书错误不要点击忽略、关闭验证或改用 HTTP。待支持字段应标记 `unsupported_by_os`，不能把不支持伪造成已采集。

部署与重启方法见仓库 `deployment/ngrok-edge/README.md`。目前电脑上的后端/ngrok不是开机自启动；提测期间保持电脑联网、不休眠，重启后重新启动服务。
