# 百度 MTC 采集操作流程说明

我们希望在每部 Android 真机上，完成一次 **App 177 项＋独立浏览器 67 项环境数据采集**，两端数据由我方后台接收并配对。请先根据以下操作评估能否实现，以及包含浏览器步骤的报价。

## 1. 双方分别做什么

- **我方提供：**采集 APK、浏览器采集网页和数据接收后台；网页自动更新采集状态，完成后显示“本机采集完成”。
- **MTC 负责：**安装并启动 App、处理跨应用跳转和浏览器首次使用页面、等待完成、记录失败原因。采集代码已由我方实现，网页打开后会自动执行。

## 2. 每部手机的具体操作

| 步骤 | MTC 脚本操作 | App／网页自动执行的工作 |
| --- | --- | --- |
| ① 启动 | 安装并启动我方 APK，保持联网 | App 自动采集 177 项数据并发起上传 |
| ② 跳转 | 跳转后继续控制浏览器 | App 自动拉起独立浏览器，打开本轮专属采集链接 |
| ③ 处理引导 | 处理欢迎页、首次使用协议、版本介绍页等；可跳过的登录／推荐页面直接跳过 | 最终应进入采集网页；停在浏览器首页不算完成 |
| ④ 等待采集 | 保持采集页可见，不关闭浏览器、不强停或卸载 App | 网页自动采集 67 项数据并上传；App 可在后台继续上传 |
| ⑤ 确认结束 | 识别网页上的“本机采集完成”，记录结果后结束本机任务 | 后台确认本轮两端数据已上传并配对，网页自动显示完成提示 |

**当前程序的实际顺序：**App 采集完成后，上传和拉起浏览器可以并行；无需人工点击跳转按钮，也无需先切回 App 等待上传提示。若最终要求严格“App 上传成功后再跳转”，需由我方调整 APK 后再交付试跑。

**需要重点解决的是第③步：**不同品牌浏览器的首次使用流程可能挡住采集网页。完成引导后必须继续进入 App 发起的本轮链接；如果链接丢失，记录现场并按约定重新发起采集。

## 3. 怎样知道上报结束

采集网页会自动更新以下状态，MTC 脚本读取页面提示即可判断是否结束：

| 页面提示 | 含义与处理 |
| --- | --- |
| `Collecting…`／`Uploading…` | 正在采集或上传，继续等待 |
| `Browser payload saved, waiting for app binding.` | 浏览器数据已收到，网页继续自动检查 App 配对状态，继续等待 |
| **本机采集完成** | 本轮 App 与浏览器数据均已上传并配对，可记录成功并结束任务 |
| **采集失败：…／配对超时：…** | 页面显示原因，记录提示及截图，按约定重试或列为失败 |

**完成状态由采集网页自动向我方后台确认。**即使浏览器先上传完成，网页也会继续等待 App；本轮两端数据配对成功后，自动更新为“本机采集完成”。MTC 只需识别该提示，无需另外查询后台。

采集网页打开后，预估几十秒至约一分钟完成，具体以试跑为准，浏览器引导操作另计。**不能以“网页已打开”或“固定等待一分钟”作为成功标准。**网页等待配对的上限为 120 秒；MTC 任务时限需覆盖安装、引导、采集及配对等待，具体时限和重试次数在试跑后确认。

## 4. 设备范围与采购

- Android **5.0／API 21 及以上**实体真机、正式系统；API 20 及以下、模拟器和预览系统不纳入。当前 APK 为 `minSdk 21 / targetSdk 36`，targetSdk 不是运行上限；API 37 及以上正式系统先试跑确认。
- 保留原有系统、WebView 和浏览器版本；设备需能运行 APK 并访问我方 HTTPS 服务。使用独立浏览器，优先系统默认浏览器，无默认时选择可用浏览器并记录；App 内 WebView 数据不能替代 Browser67。
- 个别 API／字段不支持时，由采集程序记录缺失状态；不要求通过升级环境使所有字段都有值。
- **不购买套餐，原沟通单价为 10 元／部。**希望采购全部符合条件的可用真机，预计 600+ 部；请确认加入上述浏览器操作后的最终单价、可用数量及重试费用。

## 5. 参考伪代码

```pseudo
for device in confirmed_devices:
    install_and_start_app(device)
    # App 自动采集、上传，并拉起本轮浏览器采集页
    result = "超时待确认"

    while within_agreed_timeout():
        handle_agreed_browser_welcome_and_dialogs(device)
        # 若停在首页，恢复本轮采集链接；无法恢复则记录失败
        state = read_probe_page_status(device)
        if state == "本机采集完成":
            result = "成功"
            break
        if state.starts_with("采集失败") or state.starts_with("配对超时"):
            result = "失败"
            save_error_and_screenshot(device)
            break
        wait(POLL_INTERVAL)

    save_result_and_evidence(device, result)
    # 失败／超时按约定补采，保留原记录；每轮结果记录后再释放设备
```

`read_probe_page_status` 表示读取当前采集网页的状态文字，由 MTC 按平台实现页面文字识别。建议先用少量不同品牌设备试跑，确认引导页处理和完成提示识别，再批量执行。
